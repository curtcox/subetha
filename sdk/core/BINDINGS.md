# subetha-core bindings

PLAN §10 ("SDK architecture") picks one Rust core with generated bindings:

| Target | Tool | Status |
|---|---|---|
| Kotlin (JVM/Android) | [UniFFI](https://mozilla.github.io/uniffi-rs/) 0.28 proc-macros + JNA | **Automated.** Bindings generated by `scripts/gen-bindings.sh` and committed (`sdk/kotlin/subetha-core`). CI runs the Kotlin tests against the cargo-built `libsubetha_core.so`, including the spec vectors. Android `.so`/AAR packaging is manual (cargo-ndk) |
| Swift (iOS/macOS) | UniFFI 0.28 | **Automated.** Bindings generated and committed (`sdk/swift/Sources/SubEthaCoreFFI`, `sdk/swift/ffi`). CI builds the macOS XCFramework slice and runs `swift test`; on `main` it builds the full iOS + simulator + macOS XCFramework zip as an artifact. Publishing a release (URL + checksum) is manual |
| React Native | [uniffi-bindgen-react-native](https://github.com/jhugman/uniffi-bindgen-react-native) | **Scaffold.** `sdk/react-native` re-exports the TS SDK and declares the core surface plus a `loadCore()` seam; `ubrn.config.yaml` is a starting config. Generation isn't run in CI |
| Flutter/Dart | [flutter_rust_bridge](https://github.com/fzyzcjy/flutter_rust_bridge) v2 | **Planned.** `sdk/flutter` is pure Dart (HTTP client, request signing, enrollment). Its README describes the `sdk/core-frb` plugin plan; the `DeviceSigner.signEnvelope` / `EnvelopeCrypto` seams are in place |
| Web | hand-written TS SDK (`sdk/js`), optional core WASM later | — |

## The `ffi` surface

`src/ffi.rs` holds the exported functions. They only take and return strings, byte vectors,
bools, integers, `Option`, `Vec<String>` and three records, so every generator handles them
without custom type mapping. Envelopes cross the boundary as JSON text.

| Function | Purpose |
|---|---|
| `new_device_key() -> DeviceKeyRecord` | New Ed25519 key: `seed`, `public_key`, `device_id` |
| `device_key_from_seed(seed) -> DeviceKeyRecord` | Rebuild from a stored seed |
| `new_message_id() -> String` | ULID |
| `canonicalize_json(json) -> String` | Spec §3 canonical JSON |
| `validate_envelope_json(json) -> Vec<String>` | Schema problems, empty = valid |
| `sign_envelope_json(json, seed) -> String` | Sets `sender` and `sig` (spec §4) |
| `verify_envelope_json(json) -> bool` | Never throws |
| `encrypt_envelope_json(json, key, kid) -> String` | Spec §5, random nonce |
| `decrypt_envelope_json(json, key) -> Option<String>` | `None` = wrong key or tampered |
| `sign_bytes(seed, message) -> Vec<u8>` | Raw Ed25519 signature |
| `new_request_nonce() -> String` | base64url(16 random bytes), for `X-Device-Nonce` |
| `request_signing_input(method, host, path_and_query, body, signed_headers) -> String` | `subetha-req-v2\nMETHOD\nhost\npath?query\nhex(sha256(body))` + `\nname:value` per signed header (spec §8.1) |
| `sign_request(seed, method, host, path_and_query, time, nonce?, body, headers) -> SignedRequestRecord` | `device_id`, `time`, `nonce`, `signed_headers`, `signature` for the `X-Device-*` headers. `headers` are the ones the request carries (content and routing headers must be signed). `None` draws a nonce |
| `enrollment_proof(seed, time) -> EnrollmentProofRecord` | Proof for `POST /v1/device/code` |

### Edge transports (`src/ffi_edge.rs`)

Stateless helpers: `audio_modulate`, `audio_demodulate`, `audio_resample`, `ble_chunk`,
`edge_deliver_payload` (the payload one-way links carry), `base45_encode_bytes` /
`base45_decode_text`, `lan_beacon`, `lan_parse_beacon`, `lan_new_node_id`, `lan_datagrams`.

Stateful objects (`uniffi::Object`, each a `Mutex` around the core type, safe to share across
threads):

| Object | Drive it with | Gives back |
|---|---|---|
| `EdgeGossipNode(require_signatures)` | `subscribe`, `set_relayable`, `publish(json, now)`, `handle(bytes, now)`, `prune` | `summary(now)` bytes; `EdgeHandledRecord { replies, delivered, dropped }` |
| `EdgeChunkReassembler()` | `push(chunk, now_ms)` per BLE notification/write or LAN datagram | whole gossip messages |
| `EdgeQrEncoder(payload, frame_size)` | `frame(seq)` / `frame_text(seq)` on a display timer | base45 text for alphanumeric QR codes |
| `EdgeQrDecoder()` | `push_text(text)` / `push_frame(bytes)` per camera detection | `EdgeQrProgress`, then `result()` |
| `EdgeAudioReceiver(sample_rate, window_seconds)` | `push(samples)` per microphone buffer | payloads as frames are heard |

`src/ffi_store.rs` adds `CoreOutbox` (store-and-forward queue with backoff, `to_json` /
`restore_json` for persistence) and `CoreDeduper` (spec §6).

Swift wraps them in `SubEthaCore/Edge.swift` (`Edge.modulate`, `Edge.bleChunks`, typealiases,
GATT UUIDs). Kotlin uses `org.subetha.core.ffi` directly. Both test suites check them against
`spec/vectors/edge.json` and run a gossip exchange over 23-byte BLE chunks.

`host` is what WHATWG `URL.host` gives: lowercase, with `:port` only when the port is not
the scheme's default. The Kotlin, Swift and Dart clients also implement request signing
natively (JDK / CryptoKit / pure-Dart Ed25519) so it works without the native library. Their
tests pin the same signature as `ffi::tests::request_signing`, which is cross-checked against
Node's Ed25519.

Errors map to `FfiError::Failed { msg }`, which becomes a thrown error/exception in each language.

Each function carries `#[cfg_attr(feature = "uniffi", uniffi::export)]`, and `lib.rs` calls
`uniffi::setup_scaffolding!()` when the feature is on. Without the feature, the crate
forbids `unsafe` code, has no UniFFI dependency, and the functions are plain Rust.

## Build artifacts and generation

- `crate-type = ["lib", "cdylib", "staticlib"]`. The `lib` is for Rust users and tests. The
  `cdylib` is what JNA (JVM/Android) loads, and the `staticlib` goes into the iOS/macOS
  XCFramework. Without the `uniffi` feature the extra artifacts export nothing; they cost one
  link step in `cargo test`. (This replaces the earlier plan for a separate `sdk/core-ffi`
  crate.)
- Feature `bindgen` = `uniffi` + `uniffi/cli`. It gates the `uniffi-bindgen` binary
  (`src/bin/uniffi-bindgen.rs`, the standard `uniffi::uniffi_bindgen_main()`), so the generator
  always matches the library's UniFFI version. Library builds for phones use only `uniffi`
  and don't compile clap/askama/goblin.
- `uniffi.toml` sets the Kotlin package (`org.subetha.core.ffi`) and the Swift FFI module name
  (`subetha_coreFFI`).

```bash
sdk/core/scripts/gen-bindings.sh            # build the cdylib (debug) and regenerate Kotlin + Swift
sdk/core/scripts/gen-bindings.sh --check    # CI: fail if the committed bindings are stale
sdk/swift/scripts/build-xcframework.sh      # macOS + Xcode: iOS, simulator and macOS slices
cargo test   --workspace --features subetha-core/uniffi
cargo clippy --workspace --all-targets --features subetha-core/bindgen -- -D warnings
```

The generated sources (about 56 KB of Kotlin, 34 KB of Swift and a 28 KB C header) are
**committed**. That lets Gradle and SwiftPM consumers build without cargo for the bindings.
Only the native libraries come from cargo or CI. Regenerate whenever `ffi.rs` changes.
`mobile.yml` enforces this with `--check`.

## What's automated vs. manual

| Step | Status |
|---|---|
| Generate Kotlin + Swift bindings from the cdylib | Automated (`gen-bindings.sh`), drift-checked in CI |
| Kotlin tests against the real library (JNA), spec signature/E2EE vectors | Automated (`mobile.yml` → kotlin) |
| macOS XCFramework slice + `swift test` (client + core, vectors) | Automated (`mobile.yml` → swift) |
| Full XCFramework (iOS device, simulator, macOS) | Automated on `main` as a CI artifact (`build-xcframework.sh --zip`) |
| Publish the XCFramework zip + checksum (`SUBETHA_CORE_XCFRAMEWORK_URL/_CHECKSUM`) | Manual (release step not written) |
| Android `.so` per ABI (cargo-ndk) and an AAR bundling them with `subetha-core` | Manual (commands in `sdk/kotlin/README.md`) |
| Maven Central / SwiftPM tag publishing | Manual |
| React Native Turbo Module via ubrn | Manual / scaffold (`sdk/react-native/ubrn.config.yaml`) |
| Flutter plugin via flutter_rust_bridge (`sdk/core-frb`) | Not started (plan in `sdk/flutter/README.md`) |
| Stateful edge objects (gossip node, chunk reassembler, QR encoder/decoder, audio receiver) as `uniffi::Object` | Done (`ffi_edge.rs`), plus the outbox and deduper (`ffi_store.rs`) |

## Next steps

1. **Android packaging.** Add a Gradle task (or CI job) that runs cargo-ndk for arm64-v8a,
   armeabi-v7a and x86_64 and publishes `subetha-core` as an AAR with `jniLibs` and
   `jna@aar`.
2. **Releases.** On tags, upload `subetha_coreFFI.xcframework.zip` and publish its checksum
   for `Package.swift`. Publish `org.subetha:subetha` / `subetha-core` to Maven Central.
3. **React Native.** Run `uniffi-bindgen-react-native` against `sdk/core` to produce
   `@subetha/react-native-core`, and make `loadCore()`'s consumers (`sdk/react-native`) use it
   for signing and E2EE on Hermes.
4. **Flutter.** Add `sdk/core-frb` (re-exports `subetha_core::ffi`) and generate the FRB
   plugin. Implement `CoreDeviceSigner` / `CoreEnvelopeCrypto` on top of it.
5. **Platform shims.** The edge objects are exported. Next, wire them into the sample apps'
   Edge screens: CoreBluetooth / Android BLE peripheral advertising the GATT service,
   AVAudioEngine / AudioRecord for sound, AVCapture / CameraX + a QR detector, and
   Network.framework / `MulticastSocket` for LAN.
6. **Conformance.** The Kotlin and Swift core tests load every applicable vector file:
   `canonical.json`, `topics.json`, `signatures.json`, `e2ee.json`, and `edge.json`.
