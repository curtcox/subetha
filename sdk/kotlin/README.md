# SubEtha for Kotlin (JVM + Android)

Two artifacts:

| Artifact | What | Native code |
|---|---|---|
| `org.subetha:subetha` | Client: publish, dry-run estimates, poll, subscribe (Flow or callback) with reconnect from the last id, dedupe and acks; device-signed requests and enrollment; `SubEthaException` | none (`HttpURLConnection`, kotlinx-coroutines, kotlinx-serialization-json) |
| `org.subetha:subetha-core` | UniFFI bindings to the Rust core (`sdk/core`): `CoreDeviceSigner` (requests + envelope signatures), `CoreEnvelopeCrypto` (verify, E2EE) | `libsubetha_core` via JNA |

```kotlin
val client = SubEtha(token = System.getenv("SUBETHA_TOKEN"))

client.publish("@me/doorbell", "ding", PublishOptions(title = "Front door", priority = 4))

val est = client.estimate("@me/doorbell", "ding", PublishOptions(route = Route(RouteMode.ALL, maxCostUsd = 0.05)))
println("worst case \$${est.estimateUsd}: ${est.plan}")

client.subscribe("@me/doorbell", SubscribeOptions(since = "10m")).collect { m ->
    println("${m.title}: ${m.message}")   // acked after this block returns
}
```

Java / non-coroutine callers use the callback form, which returns a `Subscription`:

```java
Subscription sub = client.subscribe(List.of("@me/doorbell"), new SubscribeOptions(), m -> System.out.println(m.getMessage()));
sub.close();
```

### Subscribe semantics

- Cold `Flow`: collecting opens `GET /<topics>/json` (or polls with `SubscribeTransport.POLL`).
- Reconnects with exponential backoff (`initialBackoffMs` … `maxBackoffMs`, or `Retry-After`) and
  resumes with `since=<last id>`. `onOpen` fires on each (re)connect, `onError` on each retryable error.
- 4xx errors other than 408/429 (bad token, no balance, forbidden) end the flow with `SubEthaException`.
- Ids are deduped case-insensitively (spec §6); expired messages are dropped.
- With `autoAck` (default) each message is acked via `POST /v1/ack` once the collector returns.
- Cancelling the collector returns at once. The JSON stream is read on a daemon thread, which
  exits on the next keepalive because `HttpURLConnection` can't abort a read in progress. Plug in
  OkHttp through `HttpTransport` if you want reads cancelled straight away.

### Device keys

```kotlin
val signer = CoreDeviceSigner.generate()          // or JdkDeviceSigner on a Java 15+ JVM
val client = SubEtha(deviceSigner = signer)
val code = client.startEnrollment(name = "Pixel 9") // show code.userCode / open code.verificationUriComplete
client.awaitEnrollment(code)                        // after the user approves in the console

val device = SubEtha(deviceSigner = signer, signRequests = true) // X-Device-Id/Time/Nonce/Signature, no token
```

`JdkDeviceSigner` uses the JDK's Ed25519 (deterministic, byte-identical to the core) and needs
no native library, but most Android versions lack it. `CoreDeviceSigner` works everywhere the
core library loads, and also signs envelopes (`PublishOptions(sign = true)`, the default when a
signer is configured). E2EE needs `crypto = CoreEnvelopeCrypto` plus `topicKeys`.

## Building and testing

```bash
cd sdk/kotlin
gradle test                                    # client tests; core tests skip without the library
cargo build -p subetha-core --features uniffi  # from the repo root: builds target/debug/libsubetha_core.so
gradle test                                    # now CoreTest runs against the real library (spec vectors too)
gradle test -Psubetha.core.lib=/path/to/dir    # use a library somewhere else
```

The tests use a local `com.sun.net.httpserver` mock relay. The UniFFI Kotlin source
(`subetha-core/src/main/kotlin/org/subetha/core/ffi/subetha_core.kt`) is generated by
`sdk/core/scripts/gen-bindings.sh` and committed. CI fails if it is stale.

## Android

- `org.subetha:subetha` is plain JVM bytecode (Java 11 target) and works as-is (`INTERNET` permission).
- For `subetha-core`, build the `.so` per ABI with [cargo-ndk](https://github.com/bbqsrc/cargo-ndk)
  and put it in `src/main/jniLibs/<abi>/libsubetha_core.so`:
  ```bash
  cargo ndk -t arm64-v8a -t armeabi-v7a -t x86_64 -o app/src/main/jniLibs build -p subetha-core --features uniffi --release
  ```
  Then depend on `net.java.dev.jna:jna:5.15.0@aar` (exclude the plain `jna` jar). An AAR that
  bundles these is planned (see `sdk/core/BINDINGS.md`).
- `samples/android` is a Compose app that uses this SDK.
