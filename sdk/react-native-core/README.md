# @subetha/react-native-core

The SubEtha Rust core (`sdk/core`) as a React Native Turbo Module. Everything in `src/`,
`cpp/`, `android/` and `ios/` (except the few hand-written files listed below) is generated by
[uniffi-bindgen-react-native](https://github.com/jhugman/uniffi-bindgen-react-native) (ubrn)
0.28 from the same UniFFI surface as the Swift and Kotlin bindings
([`sdk/core/BINDINGS.md`](../core/BINDINGS.md)), and is committed. CI regenerates it and fails
if the committed copy is stale.

It gives Hermes what it lacks: Ed25519 device keys and signatures, envelope verification, E2EE,
request signing, plus the core's edge objects (gossip node, BLE chunk reassembler, QR fountain
codec, audio receiver), the store-and-forward outbox and the deduper.

```ts
import { newDeviceKey, signEnvelopeJson, verifyEnvelopeJson, EdgeGossipNode } from "@subetha/react-native-core";

const key = newDeviceKey();                         // { seed, publicKey, deviceId }; keep the seed in the keystore
const signed = signEnvelopeJson(JSON.stringify(env), key.seed);
verifyEnvelopeJson(signed);                         // true
```

With `@subetha/react-native`, hand it to `loadCore` (Metro needs the literal `require`):

```ts
import { loadCore } from "@subetha/react-native";
import { createEdgeNode } from "@subetha/react-native/edge";

const core = await loadCore(() => require("@subetha/react-native-core"));
const node = createEdgeNode({ core });              // verifies signed gossip with the core
```

`loadCore` returns null if the package isn't installed, so apps can treat it as optional.

## Building

The native library is built per target and isn't committed:

```bash
cargo install cargo-ndk                       # Android, with ANDROID_NDK_HOME set
npx ubrn build android --config ubrn.config.yaml --release   # → android/src/main/jniLibs/<abi>/libsubetha_core.a
npx ubrn build ios --config ubrn.config.yaml --release       # → build/SubEthaCoreFramework.xcframework (macOS)
```

Then install the package into the app. It must be installed as a copy, not a symlink, so its
CMake build can find `uniffi-bindgen-react-native` in the app's `node_modules`: with npm,
`npm install --install-links ../path/to/sdk/react-native-core` (the Expo sample sets
`install-links` in its `.npmrc`). React Native autolinking picks up `android/` and
`sub-etha-core.podspec`; it needs the New Architecture (the default from React Native 0.76).

## Regenerating

```bash
sdk/core/scripts/gen-rn-bindings.sh           # after changing sdk/core's exported API
sdk/core/scripts/gen-rn-bindings.sh --check   # what CI runs
npm install --legacy-peer-deps && npx tsc -p .   # typecheck the bindings against @subetha/react-native's SubEthaCore
```

Hand-written files: `package.json`, `ubrn.config.yaml`, `tsconfig.json`, `test/compat.ts`,
`android/gradle.properties` (defaults when the app doesn't set them),
`android/src/main/AndroidManifestNew.xml` (which ubrn's `build.gradle` uses with AGP ≥ 7.3),
and this README.
