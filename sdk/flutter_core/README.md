# subetha_core (Flutter)

The SubEtha Rust core (`sdk/core`) for Flutter, through
[flutter_rust_bridge](https://cjycode.com/flutter_rust_bridge/) v2 (PLAN §10). It adds what the
pure-Dart [`subetha`](../flutter) package can't do on its own:

- **Envelope signatures and E2EE** (spec §4, §5): `CoreDeviceSigner` and `CoreEnvelopeCrypto`
  plug into `SubEtha(signer: ..., crypto: ..., topicKeys: ...)`.
- **Edge transports** (spec §11), as drivers that only need the platform to move bytes and
  samples, the same as the Kotlin, Swift, and TypeScript SDKs: `AudioLink` (sound),
  `QrSender`/`QrReceiver` (animated QR), `BleLink` and `GossipSession` (Bluetooth LE or any
  two-way link), `EdgeBridge` (relay ↔ edge, for a phone that's the gateway for offline ones),
  `deliverPayload`/`acceptPayload`, and the core objects underneath
  (`GossipNode`, `QrEncoder`, `QrDecoder`, `AudioReceiver`, `ChunkReassembler`).

Call `await SubEthaCore.init()` once (for example in `main()`) before using any of it. Every
call is synchronous: they are all fast.

## Layout

| Path | What |
|---|---|
| `rust/` | The `subetha_core_frb` crate: `src/api/core.rs` and `src/api/edge.rs` wrap `subetha_core::ffi` / `ffi_edge`. Its own Cargo workspace and lockfile. |
| `rust/src/frb_generated.rs`, `lib/src/rust/` | Generated by `flutter_rust_bridge_codegen generate` (committed; don't edit). |
| `lib/src/core.dart`, `lib/src/edge.dart` | `SubEthaCore.init`, the `package:subetha` seams, and the edge drivers. |
| `cargokit/`, `android/`, `ios/`, `macos/`, `linux/`, `windows/` | flutter_rust_bridge's plugin template: cargokit builds the crate for each platform when an app builds (needs Rust, plus the Android NDK or Xcode). |

## Developing

```bash
cargo install flutter_rust_bridge_codegen --version 2.13.0 --locked
cd sdk/flutter_core
flutter_rust_bridge_codegen generate       # after changing rust/src/api
cargo build --manifest-path rust/Cargo.toml
flutter test                               # loads rust/target/debug/libsubetha_core_frb.*
```

The tests run the shared vectors in `spec/vectors` (signatures, canonical JSON, topics, E2EE)
and the edge drivers back to back. CI runs them in `.github/workflows/mobile.yml` (job
`flutter-core`).

Platform shims for BLE (for example `flutter_blue_plus`, plus a peripheral plugin), audio, and
the camera aren't part of this package. The Android and iOS sample apps show what they do
(`samples/android`, `samples/ios`; see `docs/edge.md`).
